04 / COMPLIANCE

Compliance Frameworks

Technical findings only help if they map to a standard someone can act on. These are the frameworks I assess against.

CMMC

Cybersecurity Maturity Model Certification

A tiered DoD contractor requirement that grades an organization's cybersecurity maturity, from basic hygiene up to advanced, proactive practices, before it can handle defense-related work.

NIST SP 800-171

Protecting Controlled Unclassified Information

A set of security requirements for non-federal systems that store or process Controlled Unclassified Information — the technical baseline that CMMC largely builds on.

PCI DSS

Payment Card Industry Data Security Standard

An industry-mandated standard for any organization that stores, processes, or transmits cardholder data — covering network segmentation, encryption, access control, and logging.

OWASP TOP 10

Web Application Security Risks

The industry-standard reference for the most critical web application risks — injection, broken access control, misconfiguration, and more. I use it to structure and prioritize web app assessments.

// WHY THIS MATTERS

Security Is Easy to Postpone

— and that's exactly why it's worth doing early.

Most teams treat security as a checkbox instead of a habit. A firewall gets set up once, a policy gets written once, and everyone moves on assuming the job is done. Even well-established organizations with real budgets can fall into the same trap: assuming scale and reputation are protection in themselves.

They usually aren't enough on their own. The issues that cause the most damage rarely start with something exotic — it's often something small: a reused password, an unpatched server, an API key nobody rotated.

By the time the damage is visible — downtime, a breach, a scramble to recover — it's harder and more expensive to fix than it would have been to catch early. That's the whole case for testing things before they're forced to prove themselves.

// WHAT WAITING ACTUALLY COSTS
Data doesn't come back
Once customer records, credentials, or internal documents are exposed, there's no undo — only disclosure, cleanup, and rebuilding trust.
Downtime adds up fast
Every hour systems are frozen for incident response is an hour of lost revenue, missed transactions, and idle staff.
Trust is the hardest part to rebuild
People forgive downtime. They're a lot less forgiving when they find out their data wasn't protected in the first place.
"Security isn't about being untouchable. It's about knowing where you're exposed — and closing that gap before someone else finds it."
— the mindset behind every assessment I run
// FIELD NOTES

Notes From The Field

Short lessons pulled from actually running assessments — not theory.

01

Recon Is Half the Battle

Most engagements are won or lost before a single exploit runs. Time spent mapping subdomains, open ports, and exposed services quietly decides how the rest of the assessment goes — rushing this step almost always means missing the finding that mattered.

02

A False Positive Still Costs Trust

Flooding a report with unverified findings doesn't make an assessment look thorough — it makes it look sloppy. Every scanner hit deserves manual confirmation before it earns a place in the final report.

03

Compliance Isn't Security, But It's a Start

Passing an audit and being secure are not the same thing. Frameworks like CMMC, NIST SP 800-171, and PCI DSS give a baseline everyone can be measured against — the real work is closing the gap between "compliant" and "actually resilient."

05 / PROJECT

Featured Build

A full-stack security assessment tool I designed and built from the ground up.

Obsidian

Python / Flask Web App

A full-stack, web-based vulnerability scanner I built to make security assessments faster and easier to read. It runs 16 automated checks — port scanning, SSL/TLS auditing, WordPress and database enumeration, backup-file exposure across 210+ paths, .env / .git exposure, open redirect, and CORS misconfiguration — and streams results back in real time instead of making you wait for one long report. Findings are automatically sorted by severity (Critical → Secure), and the whole thing works comfortably from a phone thanks to a mobile-responsive UI.

Beyond scanning, Obsidian can generate a polished PDF report in one click and includes controlled exploitation modules — WordPress and MySQL brute-force testing, FTP access checks — built strictly for authorized security testing on systems you own or have permission to assess.
